# code-review 编码规范

本规范用于指导代码审查流程和审查者行为。

## 核心原则

- 代码审查是「童子军规则」的最后一道防线
- 审查目标：确保正确性、可维护性、安全性、效率、知识共享

## 审查流程

```
1. 理解需求 → 阅读 PR 描述和任务描述
2. 快速浏览 → 了解整体结构和改动范围
3. 逐文件审查 → 按优先级检查
4. 汇总反馈 → 按严重程度分类
5. 给出结论 → Approve / Request Changes / Comment
```

## 问题严重程度

| 级别 | 标记 | 处理 |
|------|------|------|
| **阻塞性** | 🔴 Must Fix | 必须阻止合并 |
| **建议性** | 🟡 Should Fix | 建议修复，可合并 |
| **优化性** | 💭 Nit | 可忽略或作为建议 |

## 阻塞性问题

出现以下问题时，必须阻止合并：

- **功能性**：逻辑错误、边界条件未处理、回归、API 契约破坏
- **安全性**：注入、权限绕过、敏感数据泄露
- **稳定性**：内存泄漏、未捕获异常、线程安全、资源泄漏

## 建议性问题

以下问题建议修复，可以合并但不推荐：

- 可维护性：重复代码、过长函数、命名不清
- 代码质量：违反 SOLID、错误处理不当、硬编码常量
- 性能：N+1 查询、不必要的重渲染

## 优化性问题

以下问题可以忽略或作为建议：

- 代码风格偏好（已有规范除外）
- 可以进一步简化的代码
- 命名可以更优雅

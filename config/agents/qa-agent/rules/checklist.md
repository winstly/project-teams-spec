# QA 验证清单

本规范整合软件测试最佳实践，为 QA 验证者提供统一的质量检查标准。

## QA 验证的核心目标

QA 验证不仅仅是找缺陷，而是：

1. **确保功能正确** — 需求功能完整实现，边界条件处理完备
2. **确保测试覆盖** — 关键路径、异常场景、回归风险全覆盖
3. **确保质量达标** — 性能、安全、可访问性符合标准
4. **确保文档同步** — 测试文档与代码变更同步更新
5. **持续改进** — 沉淀经验，优化测试策略

> 测试是质量的门卫，QA 是交付的信使。

## 验证流程

```
1. 理解需求 → 阅读 PR 描述和验收标准
2. 分析测试计划 → 检查测试用例覆盖率
3. 执行测试 → 功能、边界、异常、回归
4. 分析结果 → 缺陷分类、优先级排序
5. 出具报告 → 测试结论、质量评估
```

## 阻塞性问题 (🔴 Must Fix)

出现以下问题时，必须阻止发布：

### 功能性
- [ ] 核心功能不可用
- [ ] 边界条件未处理导致崩溃
- [ ] 破坏已有功能（回归）
- [ ] 数据一致性错误
- [ ] 状态机流转异常

### 测试覆盖
- [ ] 核心业务逻辑无测试
- [ ] 关键路径未覆盖
- [ ] 边界值无测试
- [ ] 异常路径无处理验证

### 安全/性能
- [ ] 安全漏洞（注入、越权、敏感数据暴露）
- [ ] 性能严重不达标（响应时间 > 阈值 3 倍）
- [ ] 资源泄漏
- [ ] 并发问题

## 建议性问题 (🟡 Should Fix)

以下问题建议修复，可以发布但不推荐：

### 功能完整性
- [ ] 边缘场景未测试
- [ ] 错误提示不友好
- [ ] 日志不充分
- [ ] 缺少必要的容错处理

### 测试质量
- [ ] 测试用例命名不清晰
- [ ] 测试数据硬编码
- [ ] 缺少参数化测试
- [ ] 测试执行时间过长

### 可维护性
- [ ] 测试代码重复
- [ ] 测试逻辑过于复杂
- [ ] 缺少测试文档
- [ ] 测试环境配置复杂

## 优化性问题 (💭 Nit)

以下问题可以忽略或作为建议：

- [ ] 测试覆盖率可以更高
- [ ] 可以使用数据驱动测试
- [ ] 测试执行顺序优化
- [ ] 可以添加性能基准测试

## 边界条件测试示例

| 场景 | 测试点 | 预期结果 |
|------|--------|----------|
| 字符串长度 | 0, 1, 255, 256, 1000 字符 | 处理正确，无异常 |
| 数值范围 | 最小值, 最大值, 临界值 | 边界值处理正确 |
| 空值处理 | null, undefined, 空字符串 | 降级处理或明确提示 |
| 并发 | 100 并发请求 | 无竞态条件，数据一致 |
| 大数据量 | 10000 条记录 | 分页/流式处理正常 |

## 缺陷报告模板

### 缺陷基本信息
```
缺陷ID: QA-2026-001
标题: 用户名包含特殊字符时注册失败
严重程度: High
优先级: P2
环境: Chrome 120 / macOS
```

### 复现步骤
1. 打开注册页面
2. 用户名输入 `user'name`
3. 点击注册按钮
4. **预期**: 显示友好错误提示或正确处理
5. **实际**: 页面崩溃 / 500 错误

### 根因分析
- 输入未做特殊字符转义
- 后端直接拼接 SQL
- 缺乏输入验证测试

### 修复建议
- 添加输入验证层
- 使用参数化查询
- 补充特殊字符测试用例

## 测试类型覆盖矩阵

| 测试类型 | 覆盖率要求 | 执行时机 |
|----------|-----------|----------|
| 单元测试 | > 70% | 每次提交 |
| 集成测试 | > 50% | 每次 PR |
| E2E 测试 | 核心路径 100% | 每次发布 |
| 性能测试 | 关键接口 | 每次发布 |
| 安全测试 | 高风险功能 | 每周 |

## 质量指标

### 测试覆盖率分级

| 覆盖率 | 等级 | 行动 |
|--------|------|------|
| < 50% | Fail | 必须补充测试 |
| 50-70% | Pass | 建议补充测试 |
| 70-85% | Good | 可接受 |
| > 85% | Excellent | 达标 |

### 代码覆盖率检查点

- [ ] 分支覆盖率 >= 70%
- [ ] 函数覆盖率 >= 80%
- [ ] 行覆盖率 >= 70%
- [ ] 关键路径 100% 覆盖

### 缺陷密度标准

| 缺陷等级 | 每千行代码允许数 | 行动 |
|----------|------------------|------|
| Critical | 0 | 必须 0 缺陷发布 |
| High | <= 2 | 允许少量 |
| Medium | <= 5 | 允许存在 |
| Low | - | 跟踪修复 |

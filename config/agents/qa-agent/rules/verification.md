# QA 验证规则

## 验证检查项

### 1. 代码质量

| 检查项 | 标准 | 严重程度 |
|--------|------|---------|
| 语法正确 | 无编译/运行时错误 | critical |
| 类型安全 | TypeScript/Java 编译通过 | critical |
| 代码风格 | 符合编码规范 | warning |
| 命名规范 | 符合命名约定 | warning |

### 2. 功能完整性

| 检查项 | 标准 | 严重程度 |
|--------|------|---------|
| 功能实现 | 所有 acceptance_criteria 满足 | critical |
| API 兼容性 | 不破坏已有 API | critical |
| 回归测试 | 已有功能不受影响 | critical |
| 边界条件 | 正确处理边界情况 | high |

### 3. 测试覆盖

| 覆盖率 | 等级 | 要求 |
|--------|------|------|
| < 50% | 不合格 | 必须补充 |
| 50-70% | 合格 | 建议补充 |
| 70-85% | 良好 | 可接受 |
| > 85% | 优秀 | 达标 |

### 4. 性能指标

| 检查项 | 标准 | 严重程度 |
|--------|------|---------|
| 启动时间 | 不超过基准的 120% | warning |
| 响应时间 | 不超过基准的 120% | warning |
| 内存占用 | 不超过基准的 150% | warning |
| 并发处理 | 满足并发需求 | high |

## 验证流程

### 阶段 1: 代码检查
1. 语法检查
2. 类型检查
3. 静态分析

### 阶段 2: 测试执行
1. 单元测试
2. 集成测试
3. E2E 测试

### 阶段 3: 覆盖率统计
1. 统计覆盖率
2. 生成报告
3. 识别盲点

### 阶段 4: 问题分类
1. 标记 critical 问题
2. 标记 high 问题
3. 标记 medium/low 问题

## 问题报告格式

```yaml
issues:
  - severity: critical
    title: "测试覆盖率不足"
    file: "src/service/user.service.ts"
    line: 42
    suggestion: "补充边界情况测试"
    impact: "用户下单可能失败"

  - severity: high
    title: "内存泄漏"
    file: "src/cache/redis.ts"
    line: 88
    suggestion: "添加超时释放"
    impact: "长期运行内存持续增长"
```
